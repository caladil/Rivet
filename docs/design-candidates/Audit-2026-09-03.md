## Phase 1 — Architectural and design review

**What holds up.** The architecture is unusually well separated for a one-person OS: adapters behind two-method ports, a pure `decide()` at the centre of supervision, a signed payload format whose verifier checks the signature before believing a single manifest byte, and a single-threaded supervisor that never takes a lock. The SDK's "handed, never taken" first article is the right contract and its absence handling is uniformly typed (`NotHanded`, `DisplayError::NotGranted`, empty socket lists), never a panic.

**Where the design breaks, in order of weight.**

1. **Declaration and enforcement have diverged, and the honesty rule that was supposed to bridge them has a hole.** ADR-015 §6 is candid that there is no mount namespace, no network namespace, no capability drop and no seccomp. `Manifest::unenforced` is the mechanism that keeps that visible, but it reports `network` only when the value is not `none` (`rivet-core/src/package/application.rs:1258`). So `network = "none"` — the value ADR-015 §5.1 defines as "no interfaces at all" — is the one value that is silently unenforced. The deployed Go `aura-controller` packages under the default `none` (`deploy/aura/controller/Cargo.toml` has no `network` key; default at `application.rs:687`) and fetches the NWS every twenty minutes (`PLAN.md` §112.5). The list is also stale in the other direction: `restart` is listed as unenforced while `applications.rs:612` maps it into the definition.

2. **Display arbitration is split three ways and only one of them is enforced.** sysd chowns `/dev/fb0`, `/dev/dri/card*` and `/dev/dri/renderD*` to the app (`rivet-core/src/service.rs:531`, `cmd/rivet-sysd/src/devices.rs:145`); the launcher holds DRM master and leases; the SDK receives the lease. With the card node chowned to it, an app can open `card0` by path and take master the moment the launcher restarts, and it can write `/dev/fb0` around the lease entirely (`examples/probes/mesa-demo` does). ADR-036 §3.1's "gets EACCES, no compatibility path" is true only for modeset ioctls while the launcher is alive. Every app also inherits fd 0 = `/dev/console`, an undeclared read-write handle on the HDMI VT (`kernel.rs:3195-3231` says stdin is left inherited; initd nulls only 1 and 2).

3. **The exit edge is not the stop edge.** `stop` closes listeners, revokes device nodes and restores the splash (`supervise.rs:2967-2983`). `note_exit` does none of it (`supervise.rs:1597`). ADR-015 §6.2 point 4, "the splash returns when the owner exits", is therefore true only when the supervisor did the stopping. A display owner that crashes leaves its uid owning the nodes and, once retries are exhausted, a dead screen. The launcher has the same asymmetry: its health poll runs only when `locked` (`launcher/main.rs:355`), so on an unlocked machine a dead app leaves the launcher believing it is handed over.

4. **ADR-036 §5.4A ("one implementation, drift impossible") is not what the tree contains.** The launcher's `qoi.rs` is byte-identical to the SDK's; its `text.rs` is the SDK's minus the glyph cache; its `drm.rs` is `screen.rs` minus double buffering; `kiosk-demo/drm.rs` is a third copy. The launcher uses `rivet_sdk` for exactly one listen socket.

5. **A single-threaded supervisor makes every blocking call a machine-wide hang.** There are three: the kiosk socket read (`kernel.rs:1806` switches an accepted stream to blocking, then reads to EOF), `run_to_completion` for the splash and git init (`kernel.rs:2405-2497`, no timeout), and the CEC adapter's blocking logical-address claim inside the convergence loop (`rivet-adapter-cec/src/lib.rs:296-303`).

6. **Lifecycle versus resources is sound in the small.** Backoff 250 ms doubling to 30 s, five attempts, permanent errnos refused without retry (ADR-017 §3.5.1 built). A kiosk app started without `RIVET_DISPLAY` returns cleanly and is retried five times then marked failed. Nothing spins. The gap is the re-issue contract below.

## Phase 2 — Code quality and maintainability

**Idiom.** Workspace lints (`unwrap_used`, `expect_used`, `panic`) are honoured in non-test code across every crate read; `#[allow]`s are confined to test modules and documented `unsafe_code` sites. SAFETY comments exist on every unsafe block. Errors are typed and named, not stringly, except in `rivet-sdk::screen`, where every failure is a `String` and `handed()` flattens `NotGranted` (carry on) into the same type as `Closed` (exit).

**Duplication** (each verified by diff or grep): QOI encoder ×2 identical; glyph rasteriser ×2 drifted; DRM modeset ×3; box-filter blur in launcher `farewell.rs` and splash; `Errno` declared four times across adapter ports; hex decoder ×4; the stop-edge cleanup duplicated in `stop` and `stop_adopted`; three near-identical request `Watch` modules in sysd.

**Size.** `Supervisor::start` ≈ 614 lines, sysd `main::run` ≈ 900, launcher `main()` ≈ 690 with all state as locals (untestable), `LibcKernel::wait` and `spawn` ≈ 250 each.

**Errors swallowed.** `let _ = kiosk::ask(&Request::Return)` in the launcher's `put_back` (`main.rs:953`); `F_SETFL` results ignored in `Capture::capture` (`kernel.rs:1989`) and kiosk-demo; env values with interior NUL silently dropped at spawn (`kernel.rs:3170`); `Journal::emit` "never fails" but uses `eprint!`, which panics on EPIPE.

**Loops without backoff.** None found. The exit-0-under-`restart = "always"` pattern in every kiosk app is bounded by the give-up latch, not by the app.

**Tests that cannot be right.** `aura-renderer/src/controller.rs:765-775` asserts `Command::Unhandled("rotate_corner")`; the function returns `Command::RotateCorner(..)` at `:479`. `Command` derives `PartialEq`, so the test fails as written. `FakeKernel` implements none of `take_kiosk_lease`, `open_display`, `send_display`, `close_display`, so the whole lease hand-over path runs only on hardware. The `aura-probe` floor measurement still assumes a single-buffered blit that no longer exists.

**Documentation drift.** ADR-036 §3 and §5.4A still say the lease is "ruled, unbuilt"; `rivet-sdk/src/lib.rs` says `[dependencies]` is empty and "every other module is unsafe-free" while `screen.rs` carries thirty unsafe blocks; SPEC-03 §3 has no row for the settings file or `/run/rivet/display-hours`; `tools/buildroot/README.md` still claims `BR2_STATIC_LIBS=y`; `cargo-rivet/src/elf.rs:26` claims an aarch64 refusal the code does not make; `examples/README.md` does not mention `examples/aura/`.

## Phase 3 — Security and platform audit

### [CRITICAL] TLS pinning can be bypassed by anyone who knows a pinned public key
- Where: `rivet-tls/src/lib.rs:208-216` (`public_key_in_certificate`), `:243-253` (`check`), `:283-309`.
- The pin is taken from the **first** 44-byte window anywhere in the DER that starts with the Ed25519 SPKI prefix. The handshake signature is then verified by rustls against the certificate's **real** SubjectPublicKeyInfo. Issuer and subject precede the SPKI in a TBSCertificate, so a self-signed certificate on the attacker's own key with a pinned public key planted in its subject CN passes `check`, and `verify_tls13_signature` passes because the attacker holds the key that actually signed. The doc comment's claim that the shortcut "can only refuse, never admit" is inverted. Both directions: impersonate an operator to a board (full `rivet mcp`, `mark_reached`), or a board to `rivet-fleet`. Board public keys are public by design; operator public keys are in every fleet register.
- Fix: verify possession against the pinned key itself, and restrict the scheme:
```rust
fn verify_tls13_signature(&self, message: &[u8], cert: &CertificateDer<'_>, dss: &DigitallySignedStruct)
    -> Result<HandshakeSignatureValid, rustls::Error> {
    if dss.scheme != SignatureScheme::ED25519 {
        return Err(rustls::Error::PeerIncompatible(PeerIncompatible::NoSignatureSchemesInCommon));
    }
    let spki = rustls_webpki::EndEntityCert::try_from(cert)
        .map_err(|_| refuse(Error::NotEd25519))?
        .subject_public_key_info();                       // the key the handshake is signed with
    let key: Pin = spki.as_ref().strip_prefix(&SPKI_ED25519_PREFIX)
        .and_then(|k| k.try_into().ok()).ok_or_else(|| refuse(Error::NotEd25519))?;
    if !self.pins.contains(&key) { return Err(refuse(Error::NotPinned)); }
    ring::signature::UnparsedPublicKey::new(&ring::signature::ED25519, &key)
        .verify(message, dss.signature())
        .map(|()| HandshakeSignatureValid::assertion())
        .map_err(|_| rustls::Error::InvalidCertificate(CertificateError::BadSignature))
}
fn supported_verify_schemes(&self) -> Vec<SignatureScheme> { vec![SignatureScheme::ED25519] }
```
Apply to both TLS 1.2 and 1.3 arms on both verifier impls, make `check` parse the SPKI the same way, and add a test that plants a pinned key in the issuer CN of a certificate signed by a different key.

### [CRITICAL] Root truncates a file inside an app-owned 0700 directory through symlinks
- Where: `cmd/rivet-sysd/src/runtime.rs:214` writes `rivet_core::settings::path(volume, name)` = `<volume>/app/<name>/data/settings` (`rivet-core/src/settings.rs:57`); `data/` is owned by the app uid; `kernel.rs:2561-2578` opens with `create+truncate` and then `set_permissions` by path. Both follow symlinks. Runs at boot and on every reload.
- An unprivileged application replaces `data/settings` with a symlink to `/state/config/<document>`, the device identity seed, another app's data, or the journal: sysd truncates it, writes settings text into it and chmods it 0644. A FIFO at that path blocks the open and freezes the supervisor.
- Fix: never write by path below an app-owned directory. Either move the settings file up to the root-owned `<app>/` directory, or:
```rust
let file = OpenOptions::new().write(true).create(true).truncate(false)
    .custom_flags(libc::O_NOFOLLOW | libc::O_NONBLOCK | libc::O_CLOEXEC).mode(mode).open(path)?;
let meta = file.metadata()?;
if !meta.file_type().is_file() || meta.nlink() != 1 { return Err(Errno::EINVAL); }
file.set_len(0)?; file.write_all(contents)?;
file.set_permissions(Permissions::from_mode(mode))?;   // fchmod on the descriptor, not the path
```

- Where: `rivet-core/src/package/application.rs:1256-1260`; no `Network::` reference exists anywhere in `cmd/rivet-sysd`; `deploy/aura/controller/Cargo.toml` (no `network` key, defaults to `none`), fetching NWS per `PLAN.md` §112.5.

and `network = "egress"` in `deploy/aura/controller/Cargo.toml`.

### [HIGH] The SDK's headline constructor makes the re-issue contract impossible to honour, and rebuilding leaks
- Where: `rivet-sdk/src/screen.rs:920-928` drops the `Channel` at end of scope; `display.rs` says of exactly this "would work until the first re-issue and then never draw again"; `Screen` has no `Drop`; `drive()` leaks `drmModeGetResources` and the front page on every early return (`:655-698`). Consumers `aura-renderer/main.rs:168`, `template-kiosk/main.rs:66`, `aura-probe` never call `next()` again.
- SPEC-03 §3.7 and ADR-036 §8.1 make accepting a second descriptor the obligation `devices = ["display"]` carries. As shipped no consumer can, and if it could, each rebuild leaks the revoked fd and two full-screen CMA dumb buffers (16 MB at 1080p). *(Launcher-side re-issue is also unbuilt, PLAN §106.3 — the SDK has locked in the wrong API shape before it arrives.)*
- Fix:
```rust
pub struct Handed { pub channel: Channel, pub screen: Screen }
pub fn handed() -> Result<Handed, DisplayError> {
    let channel = Channel::from_env()?;
    let fd = channel.next()?;                       // OwnedFd, closed if take_leased fails
    let screen = take_leased(fd).map_err(DisplayError::Failed)?;
    Ok(Handed { channel, screen })
}
impl Channel {
    pub fn try_next(&self) -> Result<Option<OwnedFd>, DisplayError> { /* recvmsg + MSG_DONTWAIT; EAGAIN => Ok(None) */ }
}
impl Drop for Screen {
    fn drop(&mut self) {
        if !self.owns_fd { return; }               // master path keeps everything until exit
        for p in self.pages.drain(..) { discard(self.fd, p); }
        unsafe { libc::close(self.fd) };
    }
}
```
with `Channel::next` also looping on `EINTR` as `await_flip` already does.

### [HIGH] `listen::Socket` lets safe code close any descriptor
- Where: `rivet-sdk/src/listen.rs:43-50` (`pub fd`, `Clone`), `:85-95` (`into_tcp_listener` is safe and calls `from_raw_fd`), `:125` (`sockets()` re-callable, returns the same fds every time).
- The SAFETY note ("the only constructor, never the same fd twice") is false three ways. Two `TcpListener`s over one fd, or `Socket { fd: 4, .. }` in safe code, closes the display channel or a live listener on drop.

```rust
pub fn sockets() -> Vec<Socket> {

    from_parts(/* as today */)
}
```

### [HIGH] Every application inherits fd 0 = `/dev/console`
- Where: `cmd/rivet-sysd/src/kernel.rs:3195-3231` (stdin deliberately left inherited); `cmd/rivet-initd/src/kernel.rs:762-776` nulls only 1 and 2.
- An unprivileged app holds an `O_RDWR` handle on the HDMI VT: it can write to the screen, read console keystrokes and issue VT ioctls, none of it declared.
- Fix, in the `pre_exec` closure after the sigmask reset:
```rust
let null = libc::open(c"/dev/null".as_ptr(), libc::O_RDONLY | libc::O_CLOEXEC);
if null < 0 || libc::dup2(null, 0) < 0 { return Err(std::io::Error::last_os_error()); }
libc::setsid();   // and no controlling tty to reacquire via /dev/tty
```

### [HIGH] A stalled launcher hangs the supervisor
- Where: `cmd/rivet-sysd/src/kernel.rs:1806` (`set_nonblocking(false)` on the accepted kiosk stream), `:1813` (`recv_with_fd`), `:1826-1831` (`read_to_string` to EOF). The socket is owned by an unprivileged uid.
- A connect with no write, or no close of the write half, blocks sysd forever: no reaping, no convergence, SIGTERM unread, initd SIGKILLs it after 5 s and reboots with every service orphaned. The query socket has the same shape (root-only, so a bug rather than an exposure).
- Fix: keep the accepted stream non-blocking, park it in the poll set with the ingest deadline, or make the protocol one `SOCK_SEQPACKET` datagram so one `recvmsg` is the whole request.

### [HIGH] Nothing is released on the exit edge
- Where: `supervise.rs:1597-1682` (`note_exit`) versus `:2930-2984` (`stop`). `close_display` has no caller anywhere.
- A `oneshot` that finishes leaves its port listening in sysd for the life of the boot; a display owner that crashes keeps its uid on the device nodes and the splash never returns.
- Fix: factor the cleanup out of `stop`/`stop_adopted` into `release(index)` and call it from `note_exit` on the non-`Stopping` path; clear `display_selection` when the exiting service is the selection.

### [HIGH] Switching display owners in one pass can revoke the new owner's nodes
- Where: `supervise.rs:1734-1746` (per-index decide+perform), `devices.rs:170-190` (revoke takes the declaration and chowns everything back to root unconditionally). When B sorts before A, `Start(B)` then `Stop(A)` chowns `/dev/input/*` and `/dev/fb0` to root after B spawned.
- Fix: two-phase convergence (all stops, then all starts) and a revoke that skips classes another enabled declarer still holds.

### [HIGH] Descriptor shuffle before exec can hand an app the wrong socket
- Where: `kernel.rs:3271-3320`. Listeners are `dup2`'d to `3+i` in order, then the display end to `3+n`, with only the exact `source == target` case special-cased. A source that sits inside the target range is overwritten before it is copied; `RIVET_DISPLAY` then names a listening socket and the app blocks forever in `recvmsg`. Latent and silent.
- Fix: relocate every source above the range first (`fcntl(F_DUPFD_CLOEXEC, ceiling)`), then place them.

### [HIGH] No capability bounding-set drop, no `PR_SET_NO_NEW_PRIVS`, no pids limit *(known in outline, ADR-015 §6)*
- Where: `kernel.rs:3703-3738` (`drop_privilege`: setgroups/setgid/setuid only); `:3571-3592` (only `memory.max`, only when declared). Application volumes mount `exec` (ADR-031 §5), so a setuid file on one hands root straight back; nothing bounds process count.
- Fix, before the uid drop, all async-signal-safe:
```rust
if libc::prctl(libc::PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) != 0 { return Err(last_os_error()); }
let mut cap = 0;
while libc::prctl(libc::PR_CAPBSET_READ, cap, 0, 0, 0) >= 0 { libc::prctl(libc::PR_CAPBSET_DROP, cap, 0, 0, 0); cap += 1; }
let lim = libc::rlimit { rlim_cur: 64, rlim_max: 64 };
libc::setrlimit(libc::RLIMIT_NPROC, &raw const lim);
```
and write `pids.max` beside `memory.max` unconditionally.

### [HIGH] rivet-mcpd: no connection cap, no socket timeouts
- Where: `cmd/rivet-mcpd/src/main.rs:733-768` (thread per accept, unbounded), `transport.rs:182-200` (handshake loop with no deadline). No `set_read_timeout` in the crate.
- An unauthenticated peer opens N idle TCP connections; each costs a thread and an fd before any pin is checked; at the fd limit every operator is locked out of a headless board. Given the pinning bypass above this is reachable by anyone.
- Fix: an `AtomicUsize` live-connection counter refused at 16, `set_read_timeout`/`set_write_timeout` of 10 s before the handshake, relaxed to an idle limit after.

### [HIGH] rivet-fleetd: no manifest, cross-site request forgery, one-thread one-kilobyte server

```sh
READELF="$BR_OUTPUT/host/bin/aarch64-linux-readelf"

must_be_static() {

for b in $OURS; do must_be_static "$STAGED/$b"; done
```

### MEDIUM (build)
- `cargo rivet package` never reads `e_machine` (`elf.rs:103-113` checks only class and endianness), so an x86_64 static binary is signed and named `aarch64`; add `if u16_at(bytes, 18)? != 183 { return Err(ElfFault::NotAarch64) }`.
- Two silent degradations produce a normally-named card: missing `fdtoverlay` (no `/dev/dri`) and a missing Buildroot kernel (falls back to the QEMU kernel, fetched by `scp` with no digest) both continue (`build.sh:353-362`, `:513-521`).
- Packaged applications ship unstripped DWARF whenever under the 16 MiB cap (`out/rivet-launcher-0.1.61` is 10.6 MB with debug info; stripped sysd is 1.1 MB from 14.4 MB); ADR-015 §4.2 hashes the program at every launch, so this is a 10× launch cost. Warn on `.debug_info`, or add `--strip`.
- `assets/` is not packaged: `--asset NAME=PATH` only, flat 32-byte names, no directory walker, no test. Confirms the memory note.
- No CI; `cargo deny` reports 19 duplicated crate versions (`getrandom` ×3, `syn` ×3, `windows-sys` ×3, two `digest`/`sha` stacks) and nobody runs it.

### LOW (build and performance)
- Binary size is not the constraint: stripped card binaries total ~7.5 MB on a 640 MiB slot; `nu` alone is 42 MiB. `opt-level = "z"` would buy ~2 MB at a speed cost; not recommended. `[profile.release]` as configured (LTO, one codegen unit, `panic = "abort"`, symbols kept and stripped in the recipe) is the right shape.
- Worth measuring: `-C target-cpu=cortex-a72` under `[target.aarch64-unknown-linux-musl]`; unify the `sha2 0.10` / `sha1 0.11` stacks so `rivet` and `rivet-sysd` carry one hashing implementation.
- Hot-path CPU on the Pi: launcher redraws the whole 1080p menu every 50 ms with per-pixel float blend, two `hypot` per pixel for the card stroke, an 8 MB zeroed allocation and a file read for the OS version per frame, and no glyph cache (the SDK copy has one). SDK `draw::fill_gradient_h` iterates column-major over an 8 MB canvas; `stroke_rounded` evaluates coverage over the solid interior. `aura-renderer` QOI-encodes and writes the full canvas to the SD card every 60 s forever and rebuilds `Vec<Piece>` with owned strings 30×/s for animated slots; `template-kiosk` captures every ~1.5 s and sleeps 33 ms after a blit that already waits for vblank *(pacing item known, PLAN §110.4)*. `Screen::blit` cannot copy a region *(known)*.
- Adopted services polled at 1 Hz via `cgroup.procs` for the life of the supervisor; console output flushed per record on the supervisor thread.
- A build flag referenced but never assigned in `build.sh:1087`; three `mktemp -d` directories never removed; `rustup` installer fetched unpinned; no `rust-version` in `[workspace.package]` while `crate_meta.rs` needs 1.88.

## Recommended order

1. `rivet-tls` verifier (the whole control plane rests on it), then `rivet-mcpd` connection cap and timeouts.
2. sysd: settings write out of the app-owned directory; kiosk read non-blocking; `release()` on the exit edge; null stdin; fd relocation before the shuffle; `no_new_privs` + bounding set + `pids.max`.
3. `Manifest::unenforced` for `network`, and `network = "egress"` on the controller.
4. Static gate in `tools/card/build.sh`; `e_machine` check in `cargo-rivet`.
5. SDK: `handed()` returns the channel, `Screen: Drop`, `listen::Socket` ownership; then delete the launcher's three copies and make it the SDK's first `screen` consumer as ADR-036 §5.4A rules.
6. Launcher input gating and lease bookkeeping; fleetd manifest, CSRF and request reading.
7. The doc pass: ADR-036 §3/§5.4A, `rivet-sdk/src/lib.rs`, SPEC-03 §3, `tools/buildroot/README.md`, `cargo-rivet/src/elf.rs`.
